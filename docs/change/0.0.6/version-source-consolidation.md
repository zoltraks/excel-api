# Version Source Consolidation

## Type

Maintainability

## Summary

Make `docs/contract/openapi.yaml` `info.version` the single authoritative
version value for the whole project, driven by one synchronization
mechanism that propagates it to every implementation's build metadata
and stamps synced `openapi.yaml` copies as generated.

## Coverage

`docs/contract/openapi.yaml`, `shell/sync-openapi.sh`, all four servers
(`excel-api-node`, `excel-api-java`, `excel-api-csharp`, `excel-api-rust`),
`excel-api-go`, `excel-api-test`, `docs/VERSIONING.md`, and the four
`resources/openapi.yaml` copies.

## Description

Current state - the version lives in ~12 places plus four runtime
literals:

- **Authority**: `docs/contract/openapi.yaml` `info.version` ("0.0.6")
- **Build metadata**: `package.json` + `package-lock.json` (node, test),
  `pom.xml`, `ExcelApi.csproj`, `Cargo.toml`, `version.go`
- **Runtime literals to eliminate**: `HealthController.VERSION`,
  `OpenApiController` `content.replace("${version}", "0.0.6")` (x2),
  `HealthEndpoints` `version = "0.0.6"`,
  `OpenApiEndpoints` `content.Replace("${version}", "0.0.6")`
- **Resource copies**: four `openapi.yaml` files already synced by
  `shell/sync-openapi.sh` but carrying no authoritative-source marker

Target design:

1. **One authority**: `docs/contract/openapi.yaml` `info.version` is the
   only hand-edited version value. `docs/VERSIONING.md` names it the
   source of truth and documents the sync flow.
2. **One mechanism**: extend `shell/sync-openapi.sh` (rename to
   `shell/sync.sh` acceptable) so a single run
   (a) copies the contract to all four `resources/openapi.yaml` targets
   with a generated header marker
   (`# GENERATED from docs/contract/openapi.yaml - do not edit`), and
   (b) extracts `info.version` and rewrites every build-metadata carrier:
   both `package.json` files, their `package-lock.json` version fields,
   `pom.xml`, `ExcelApi.csproj`, `Cargo.toml`, and `version.go`.
   The release routine then becomes: edit `info.version`, run the sync
   script, verify.
3. **Runtime sourcing**:
   - Node keeps `PACKAGE_VERSION` from `package.json` (already done).
   - Rust keeps `env!("CARGO_PKG_VERSION")` (already done).
   - Java and C# stop hardcoding: `HealthController`/`HealthEndpoints`
     and the OpenAPI controllers read `info.version` once from their
     embedded synced `openapi.yaml` resource at startup (both already
     load that resource for `/openapi.yaml` serving), so the served doc
     and `/health` share one value with zero literals. The
     `content.replace("${version}", ...)` calls disappear - the synced
     resource already carries the true version.
   - Go keeps a single `const Version`, regenerated by the sync script
     and marked `// Code generated by shell/sync.sh; DO NOT EDIT`.
4. **Marking**: synced `openapi.yaml` copies get the generated-comment
   header so the authority boundary is visible in every checkout.

Acceptance: `grep` for the literal version finds it only in
`docs/contract/openapi.yaml`, generated outputs, and historical docs;
one script run propagates a version change everywhere; `/health` and
`/openapi.yaml` still report identical versions on all four servers;
unit + integration ladders stay green.

## Out of Scope

- Publishing the version into git tags or release artifacts.
- Changing the version scheme or the bump cadence - only the storage
  topology.

## Verification

Implemented during the 0.0.6 autonomous SDLC run. Evidence: per-component build/typecheck/lint/unit-test loops clean (Node type-check+lint+test+build, Java compile+checkstyle+test+package, C# build+format+29 tests, Rust fmt+clippy+13 tests+release, Go build+fmt+vet+test); black-box Jest suite run natively against each server - Node 26/26, Java 26/26, C# 26/26, Rust 26/26; `/health` and `/openapi.yaml` report the contract-sourced version; error envelope key order verified `error`-then-`message`; `/auth/token` accepts form-urlencoded and JSON on all four.
